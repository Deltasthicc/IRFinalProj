# 9. Conclusions and limitations

## Conclusions

TradeMesh combines a search engine built from scratch with a verified question-answering layer. The query side detects misspelt company names with a bigram shortlist and Levenshtein confirmation (39 of 40 typo'd names resolved correctly in our test) and uses the result to filter retrieval and to split comparison questions. The answer side gives a language model five labelled passages, requires citations, and checks them with a deterministic verifier that flags invented citations and numbers that do not occur in the cited text; the system abstains when the model says the evidence is insufficient. On 20 test questions rated by two LLM passes, answers built on hybrid retrieval with reranking scored 1.70 on a 0 to 2 scale, against 1.175 for closed-book (difference +0.525, 95% interval +0.225 to +0.850) and 1.325 for BM25-based RAG (best-RAG minus BM25-RAG +0.375, interval +0.150 to +0.650). BM25-based RAG alone was not reliably better than closed-book (+0.150, interval -0.250 to +0.550), and it was worse on topical questions because it abstained on three of seven. The model's own insufficient-evidence verdict separated all 6 unanswerable test questions from 20 answerable ones, while a threshold on the retrieval score did not (precision 0.385, recall 0.833), so the final rule is the model's verdict. Retrieval quality (nDCG@5) did not predict the answer rating in our small sample (Spearman 0.007, n = 40, interval about plus or minus 0.31). All of these judgments are LLM-assisted; none was validated by a human.

## Limitations

* **Small, hand-made test sets.** The entity test has 40 typos written by us, the RAG study has 20 questions (6 to 7 per question type) and the abstention test has 6 unanswerable test questions, all clearly outside the corpus. We report paired bootstrap intervals and call a difference reliable only when its interval excludes 0; per-type numbers are descriptive. A perfect 6 of 6 on abstention has a 95% lower bound of about 0.54.
* **LLM-assisted ratings, no human validation.** Answer ratings and citation checks were made by one language model in two passes (the second in shuffled order with a stricter checklist), and retrieval judgments the same way. Cohen's kappa between the passes is 0.886 on 60 answers, but the same model made both passes and the second knew of the first, so agreement is probably optimistic. The rater (Claude) and the generator (Gemini) are different model families, closed-book answers can be recognised by having no citations, and an LLM rater can favour fluent text. The audit trail is in `docs/report_C/audit/`.
* **One small language model, one encoder.** All answers come from `gemini-3.5-flash-lite`, chosen because the free tier of larger models allows about 20 requests a day. Conclusions may not transfer to stronger models. Cached answers fix the demo, but they are tied to this model version.
* **Strict number matching.** The verifier requires a number to appear exactly (after unit normalisation). A correct but rounded or recomputed figure is flagged, and a number that is present but attached to the wrong claim is not caught. The verifier checks *presence*, not *entailment*; a citation can be real yet not support the sentence, which is why citation precision is judged separately (by LLM passes). The verifier flagged none of the 55 answered outputs on dev and test after a sentence-splitting bug was fixed, so on this data it did not demonstrate catching an error; and it cannot catch an omission such as the missing segment in question R09.
* **The retrieval score is not a usable confidence.** The score rule uses the hybrid retriever's score before reranking divided by query length. Rank fusion makes that score depend on rank positions, so unanswerable and answerable questions overlap (the 1995 Pfizer revenue question tied for the highest confidence of all 40 items). τ tuned on dev came out as 0, which turns the rule off, so abstention here is the model's own verdict. We saw the score-only numbers on the test items before choosing the verdict rule, so that choice was not fixed in advance. We did not test the cross-encoder score as a confidence.
* **Entity matcher.** Plain Levenshtein counts a transposition as two edits, so a swapped-letter ticker such as `MSTF` is missed. Names unknown to the dictionary are never detected, and a corpus word that is also a company alias can be ignored or accepted wrongly.
* **Hand-set section prior.** The weights g(Item) were set by judgement, not learned. λ was not tuned (it is 0 in all reported runs), so the section prior is not part of the reported results.
* **Scope.** English, US filings, the latest 10-K of about 20 large companies, text and tables only (charts only through the gated vision track). Questions about trends over several years are out of scope.
* **Not a financial product.** The system makes no investment claims; answers are only as good as the retrieved passages and must be checked against the filing.
